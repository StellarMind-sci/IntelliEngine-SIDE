# 日常开发流程

## 普通任务

```text
任务卡规划 → 实现 A + 实现 B + … + 实现 N → 最终审核与测试 → 合并 → 交付演示
```

- 一张任务卡服务一个用户可感知结果，可包含必要的多个实现步骤。
- 实现步骤可以连续或并行；不为文档、契约或审查本身拆出等待任务。
- 最终审核检查范围、验收条件和测试证据。阻断问题修复后复核一次；余项成为新任务卡。
- 只运行目标模块、直接依赖和验收所需测试。普通任务不创建 RFC/ADR，不要求独立集成 Issue，也不运行无关 CI。

## 高风险任务

```text
任务卡规划 + 风险提示 → 实现 A + 实现 B + … + 实现 N → 审核测试 → 交付人工审查
```

高风险：权限/授权、状态或用户数据写入、数据库、凭据、外部系统、不可逆操作、生产发布和安全隔离。

风险提示必须说明安全、兼容性、数据影响与回滚。保留相应安全测试、权限检查、溯源和回滚证据；人工审查通过前不开放此类能力。

## 任务卡

普通任务只填写：用户/产品问题、预期产品结果、范围、非目标、允许修改范围、验收条件、测试命令、风险和回滚。验收条件必须让用户可以执行：用户能力、验收入口、前置条件、操作步骤、每步预期结果、异常场景、视觉证据、自动化证据、已知限制与回滚。无界面任务改用 CLI/API/fixture/日志/结构化输出的命令及输入/输出示例。

界面、交互、可视化或演示任务还必须提供可复制的启动命令、固定演示数据或示例工程，并覆盖正常、阻断/错误、空状态；交付截图或录屏，无法提供时说明原因和替代验证方式。验收必须体现产品闭环：Knowledge Units 服务工程开发、调试、验证或 Thoughtflow，不验收为普通笔记或独立刷题页；工程证据状态与个人掌握度分开记录；未实现的界面或交互不得写成已完成。

高风险任务额外填写：安全影响、权限边界、兼容性/迁移与人工审查条件。

## 生命周期

任务状态在 GitHub。一个活动任务卡使用一个分支/worktree；合并或关闭后确认没有未提交用户改动，再移除它。只在上下文压缩、会话交接、长时间暂停、重大架构变化或高风险审查前完整重载。

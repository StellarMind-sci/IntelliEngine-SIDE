# RFC 编写器

1. 阅读产品意图、当前架构、已接受 ADR、契约和关联 Issues。
2. 确认该决定尚未被接受的 ADR 覆盖；若已覆盖，提出替代 ADR，而不是静默冲突。
3. 使用 docs/rfc/0000-template.md。
4. 定义问题、可衡量目标、非目标、所有权、数据流、公共接口、兼容性、安全、溯源、
   控制策略、替代方案、发布、回滚、可观测性和测试。
5. 区分事实与假设，列出仍需要产品负责人决定的事项。
6. 在 RFC 未确定前不要实现该提案。
7. 决定被接受后，创建 ADR 并链接后续 Issue。

输出可直接放入仓库的 Markdown，不要只给聊天式头脑风暴。
